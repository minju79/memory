# 개발 레이더 카드뉴스 — 작성 규칙

> 이 파일은 **클로드에게 주는 지시서**입니다.
> 민주오님은 링크나 헤드라인만 넣으시면 되고, 나머지는 클로드가 이 규칙대로 처리합니다.

## 사용법

```
"input/이번주.txt 로 개발 레이더 카드뉴스 만들어줘"
```

또는 대화창에 링크를 그냥 붙여넣으셔도 됩니다.

처리 흐름:

```
링크 / 헤드라인
   ↓ ① 클로드가 읽고 사실 확인
   ↓ ② 분야·진행단계 분류
   ↓ ③ 자기 문장으로 요약 + 부동산 관점 해설
   ↓ ④ data/devnews_YYYY-MM-W.json 작성
   ↓ ⑤ render.py 실행 → PNG
```

---

## ⚠ 규칙 1 — 진행 단계를 보수적으로 판정한다

**이 파이프라인에서 제일 중요한 규칙입니다.** 개발 소식은 "검토중"과 "확정"이 완전히 다른 정보입니다.
공인중개사가 검토 단계를 확정처럼 올리면 신뢰를 잃고, 실제로 분쟁이 될 수 있습니다.

개발 레이더의 **0~7 단계 체계**를 그대로 씁니다. `"stage": 3` 처럼 숫자로 넣습니다.

| stage | 이름 | 쓰는 경우 | 배지 |
|---|---|---|---|
| `0` | 관심·발언 | 정치인·기관 발언, 언론 관측 | 회색 테두리 |
| `1` | 정책검토 | 용역 발주, 타당성 조사 | 회색 테두리 |
| `2` | 계획발표 | 기본계획·구상 발표, 심의 진행 | 파란 테두리 |
| `3` | **공식지정·고시** | **고시·지정·승인 완료** | **노란색 채움** |
| `4` | 시행계획 구체화 | 사업자·예산·시행계획 확정 | 노란색 채움 |
| `5` | 입찰·발주 | 공사·용역 발주, 분양 공고 | 주황색 채움 |
| `6` | 착공·공사 | 착공 이후 | 초록 채움 |
| `7` | 준공·운영 | 준공·개통 완료 | 초록 채움 |

**3단계가 분기점입니다.** 여기서부터 배지 색이 채워지고, 카드 상단 게이지도 같이 찹니다.
고시 전(0~2)은 테두리만 있어서, 넘길 때 한눈에 "아직 확정 아님"이 보입니다.

판정 원칙:
- **애매하면 한 단계 낮춘다.** 2인지 3인지 헷갈리면 2.
- 기사 제목의 "추진", "검토", "계획", "전망", "될 듯"은 3단계가 아니다.
- 3단계는 **고시·지정·승인 문서가 확인될 때만.** 기사 하나로는 부족하다.
- 공정률·진척도 뉴스는 6단계(착공·공사)다. 개통 확정이 아니다.
- **용역 공고를 놓치지 말 것.** "타당성 조사 용역", "기본계획 수립 용역"은 1단계지만,
  2~3년 뒤 사업의 가장 이른 신호다. 남들이 모를 때 아는 정보라 콘텐츠 가치가 가장 높다.
- 판단이 안 서면 카드에 넣지 말고 민주오님께 물어본다.

## ⚠ 규칙 2 — 기사 문장을 그대로 옮기지 않는다

신문 기사 본문은 저작권이 있습니다. **사실 자체(누가·언제·무엇을)는 저작권 대상이 아니므로**,
사실만 추려 **내 문장으로 다시 씁니다.**

- ❌ 기사 문단 복사·붙여넣기
- ❌ 조사만 바꾼 재배열
- ✅ 사실을 추출해 새로 작성 + 출처 명시
- 시·구청 **보도자료**는 공공누리로 대체로 자유롭게 이용 가능하나, 출처는 반드시 표기
- 사진·도면은 가져오지 않는다 (별도 권리)

`source` 카드를 **항상 마지막에서 두 번째로** 넣습니다. 출처 표기이자 신뢰의 근거입니다.

## 규칙 3 — 분야(category)는 아래 6개만 쓴다

색이 매핑돼 있어서 다른 값을 쓰면 기본색으로 떨어집니다.

| category | 대상 |
|---|---|
| `교통` | 도로·철도·도시철도·버스·공항 |
| `재개발` | 재개발·재건축·정비사업·지구단위계획 |
| `산단` | 산업단지·데이터센터·기업 유치 |
| `주택` | 공동주택 공급·분양·사업승인 |
| `공공` | 공공시설·관광단지·공원·학교 |
| `도시계획` | 도시기본계획·용도지역 변경 |

## 규칙 4 — 해설이 차별점이다

같은 뉴스는 누구나 옮깁니다. **14년 공인중개사의 해석**이 이 계정을 보는 이유입니다.
`impact` 카드에는 기사에 없는 것만 씁니다.

- 이 소식이 **어느 동네 어떤 물건**에 영향을 주는지
- **언제** 가격·문의가 실제로 움직이는지 (착공? 고시? 개통?)
- 매매 / 전월세 / 임대 중 **무엇이 먼저** 반응하는지
- 조심할 점 (지연 리스크, 이미 반영된 기대감)

기사 요약만 반복하면 이 카드는 빼는 게 낫습니다.

## 규칙 5 — 확인 못 한 건 비운다

- 날짜를 모르면 `date` 를 비운다. **추측해서 채우지 않는다.**
- 링크가 열리지 않으면 그 항목을 빼고, 뺐다고 민주오님께 말한다.
- 헤드라인만 주어진 항목은 `points` 를 억지로 3줄 채우지 말고, 아는 만큼만 쓴다.
- 숫자(공정률·면적·사업비)는 원문에 있을 때만 쓴다.

## 카드 구성 기본값

| # | type | 내용 |
|---|---|---|
| 1 | `cover` | 훅 |
| 2 | `list` | 이번 주 전체 3~6건 요약 |
| 3~5 | `news` | 중요한 것 2~3건 상세 |
| 6 | `timeline` | 앞으로의 일정 |
| 7 | `impact` | 중개사 관점 해설 |
| 8 | `source` | 출처 + 면책 |
| 9 | `cta` | 댓글 유도 |

소식이 적은 주에는 `list` 와 `news` 한 장씩만으로 5장 구성도 괜찮습니다.
인스타 캐러셀은 최대 20장이지만, **8~10장이 완주율이 가장 좋습니다.**

## 필드 정의

```jsonc
{
  "meta": {
    "region": "광주 개발 레이더",
    "period": "2026년 8월 1주",
    "handle": "모든AI부동산",
    "sample": false,              // 검수 전에는 true (SAMPLE 워터마크)
    "disclaimer": "..."           // source 카드 하단 문구
  },
  "cards": [
    { "type": "cover",  "badge": "", "title": "줄바꿈은 \n", "subtitle": "", "note": "" },
    { "type": "list",   "title": "", "items": [{ "category": "교통", "headline": "", "sub": "지역 · 6단계 착공·공사" }] },
    { "type": "news",   "category": "교통", "stage": 6,
      "headline": "", "points": ["", "", ""], "area": "", "source": "", "date": "2026.08.04" },
    { "type": "timeline", "title": "", "items": [{ "when": "", "what": "", "note": "" }] },
    { "type": "impact", "title": "", "items": [{ "head": "", "body": "" }] },
    { "type": "source", "title": "출처", "items": [{ "title": "", "press": "", "date": "" }] },
    { "type": "cta",    "title": "", "body": "", "handle": "모든AI부동산" }
  ]
}
```

## 마지막에 실행

```bash
python3 render.py --data data/devnews_2026-08-W1.json \
                  --template template_devnews.html --out out
```

그리고 민주오님께 **PNG 와 함께 이렇게 보고합니다.**

- 각 소식의 `stage` 를 몇 단계로 판정했고 근거가 무엇인지 (특히 3단계로 올린 건)
- 확인 못 해서 뺀 항목이 있으면 무엇인지
- `sample` 을 아직 `true` 로 뒀다면 검수 후 꺼야 한다는 안내
